# Story 6.3: Create "Want to Play" Pool

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a player,
I want to create a pool to find opponents,
so that I can organize a match.

## Acceptance Criteria

- **Given** a player is on the Home Hub
- **When** they tap to create a "Want to Play" pool and submit the form
- **Then** the system records a new pool specifying the match type (1v1/2v2) and desired start conditions (fill-based or scheduled time) (FR35)

## Dev Notes

### Architecture & Implementation Guardrails

- **API Contracts & Security (AD-05):**
  - Base path: `/api/v1/pools`
  - Authentication: All endpoints require authentication. Extract user ID from `@AuthenticationPrincipal User principal`.
- **Database Design & Migrations:**
  - Flyway migration script: e.g. `src/main/resources/db/migration/V13__create_matchmaking_pools.sql`.
  - Primary keys: UUIDs generated by backend/database.
  - Foreign keys: Creator ID linked to User (`creator_id`).
  - Fields: `id`, `creator_id`, `match_type` (1v1, 2v2), `start_condition` (fill-based, scheduled_time), `scheduled_time` (timestamp), `status` (open, filled, cancelled), `created_at`, `updated_at`.
- **UX & Navigation Invariants:**
  - **Home Hub Integration:** Add "Want to Play" button to the Home Hub (Phase 2 feature as per UX Spec). 
  - Ensure the form allows selecting match type and start conditions (immediate/fill-based vs scheduled).
- **Clubhouse Styling Guidelines (UX-DR3):**
  - Followed Clubhouse "No-Line" rule: surface background tonal shifts and elevation instead of 1px solid border lines.
- **500-Line Rule (IP-04):**
  - All new and updated files strictly under 500 lines.
- **Testing Standards:**
  - **Strict AAA Pattern:** All test methods adhere to Arrange-Act-Assert separated by a single blank line, with zero structural comments.
